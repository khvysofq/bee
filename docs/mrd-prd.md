## 0. 一句话

给中国再生资源行业的中小从业者（回收站、废品贸易商）一个**每天可信的日频报价与行情简报**，并在这份可信数据之上做**情景推演**与**行业知识问答**。

---

## 1. 意图与为什么

### 1.1 你要做的是什么

一个报废品信息网站，三块能力：

1. **行情简报** —— 定期收集全国各类报废品的价格、行情，给用户简报
2. **信息推理** —— 基于历史信息与行业重大事件，推演某品类未来价格变化趋势
3. **行业问答** —— 行业知识的专业问答

### 1.2 为什么现在值得做

- 再生资源回收是万亿级市场，从业者**价格敏感、决策日频** —— 一天的报价差就是利润。
- 现有信息服务被 Mysteel / 卓创 / 富宝 / 上海钢联 等 B2B 资讯商占据，特点：贵、重、面向大企业。**中小从业者基本被挡在外面**，靠行业群和地方市场口头报价过日子。
- 空隙在于：面向中小从业者的**轻量、日频、可信**行情。差异化不太可能是「数据独家」（v1 没有），而是**轻、准，以及问答 / 推演的交互体验**。

### 1.3 为什么难（先说清，这是可行性底座）

- **数据是命门，也是最大风险。** 报价分散在地方市场、行业群，以及付费资讯源。公开渠道拿不到完整全国覆盖 ——「实时全国」在免费数据上不成立。
- **废料价格强地域性。** 同一品类同城不同价；「全国均价」是加工出来的指标，不是观测值。数据治理（品类口径、地域对齐、异常剔除）比模型更决定产品可信度。
- **预测是信任敏感点。** 简报报错可更正；点位预测报错直接毁掉信任，且在国内大宗商品信息服务有合规边界。

## 2. 目标 / 非目标 / 反目标

### 2.1 目标（v1 必须成立）

| # | 目标 | 可观测的「做到了」 |
|---|---|---|
| G1 | 给回收站与废品贸易商**日频买卖报价决策**用的可信报价 | 一批目标用户每天来看简报，并认为报价可信 |
| G2 | 覆盖 5 个核心品类的规范化报价库 | 品类 × 规格/等级 × 地域 × 日期 有稳定、可追溯、可回放的记录 |
| G3 | 每日自动更新，人不参与日常整理 | 连续多日无人工整理；异常只进队列，人只在队列与决策点出现 |
| G4 | 三块能力都有，深度按 §5 的 MVP 分层 | 见 §5.4 |

### 2.2 非目标（v1 明确不做）

- 实时 / 秒级行情（现实是日频）
- 全国全量、所有品类、所有规格的覆盖
- 价格**点位预测**承诺
- 交易撮合、收货系统、ERP、物流
- 报废汽车 / 家电**整机**回收（v1 只做再生资源品类本身）
- 移动 App（v1 是网站）
- 付费墙与商业化收入（v2 再谈，见 §6.3）

### 2.3 反目标（做成了也算失败）

- **为追求覆盖而牺牲报价可信度。** 覆盖可以慢慢长，可信度崩了就没了。
- **把 LLM 生成的数字当报价数据。** 生成内容只能是叙事，数字必须来自可追溯来源。
- **在简报里给投资 / 买卖建议。** 只给事实、变化、情景。
- **靠人每天整理数据。** 违背你定的运行方式，也不可扩张。
- **预测给点位承诺。** 一次错就毁掉简报建立起来的信任。

## 3. 约束

**来自你的决定（2026-10-26）**

1. **品类**：废钢、废铜、废铝、废纸、废塑料等再生资源品类。
2. **用户**：回收站与废品贸易商；决策 = 日频买卖报价。
3. **数据来源**：公开渠道采集 + **Agent 校验**；数据更新尽量少人参与，**人只用来做决策、发现错误**。
4. **频次**：以天为单位，定期在公开渠道 / 网站采集。
5. **成本**：v1 不采购专业数据接口；未来产品使用人多了再考虑买专业渠道接口。
6. **MVP 深度**：行情简报最深最可信；趋势预测降级为情景推演；问答做行业知识库专业问答。成功标准 = 一批目标用户每天来看简报并认为报价可信。

**来自现实**

7. 「全国」是目标不是 v1 承诺。v1 对外承诺「**日更 + 趋势**」，不承诺「实时全国」。
8. 强地域性 —— 必须做品类口径与地域对齐；「全国均价」必须标注为加工指标。
9. **合规**：公开发布行情预测内容有边界。只做情景推演、不做点位与投资建议，是风险最低的形态。网站需 ICP 备案；采集须遵守目标站 ToS / robots，低频读取公开页面。
10. **数据授权**：付费源数据有二次分发边界，未来买接口也要先确认可否对外展示。

## 4. 路线对比与选择

（完整对话版见 Paperclip 任务 DAW-27 的「方案对比」评论，id `8133b400`；这里是记录。）

| | A 日更简报站 | B 品类价格库 | C Agent 自动编辑部 |
|---|---|---|---|
| 核心产物 | 每天一份简报 | 规范化报价表 | 自动化运行管线 |
| 到第一个可见页面 | 2–4 周 | 2–3× 工程量 | 取决于底盘 |
| 护城河 | 弱 | **数据资产** | 运营成本结构 |
| 未来买专业接口 | 推倒重写 | 干净插入 | 不影响 |
| 主要风险 | 数据是副产品 | 前期慢 | 全自动数据难被信 |

**选定：B 做骨架，C 做管线运行方式，A 做对外节奏。**

- **架构走 B** —— 第一天就建规范化价格库（品类 × 规格 × 地域 × 日期 × 来源 × 校验状态），三块能力都是它的视图。这是唯一不返工的选择。
- **管线走 C** —— 采集 / 校验 / 异常隔离 / 留痕全 Agent 化，人只出现在异常队列和口径决策点上。
- **对外走 A 的节奏** —— 先出简报页，让用户在数据库还在长的时候就开始每天来。

**为什么不只做 A**：你已说未来要买专业接口，只做 A 那一步是重写。
**为什么不只做 C**：全自动是运行方式，不是产品形态。用户看不到「编辑部」，只看到报价和简报。

## 5. PRD —— 三块能力在 v1 各做到哪

### 5.1 行情简报（最深、最可信）

**形态**：每日一份，按品类组织。每个品类给出：

- **参考报价**：品类 × 规格/等级 × 地域，标注来源与更新时间
- **涨跌**：对比昨日 / 上周 / 上月
- **当日变化原因**：Agent 从公开信息摘要，**注明来源**
- **覆盖度与置信提示**：覆盖几个市场、有无异常、有无数据缺口

**可信度机制（这是产品的立身之本，不是可选项）**

- 每条报价可溯源到具体来源 URL + 抓取时间
- 变更留痕，可回看历史版本
- **异常值隔离**：不进简报，进异常队列
- 「全国均价」明确标注为加权/中位加工指标，不是观测值
- 数字来自库，不来自 LLM 生成

**明确不做**：实时刷新、点位预测、买卖建议。

### 5.2 情景推演（原「趋势预测」的降级形态）

**形态**：针对单个品类，给「若 X 则可能 Y」的推演，不做点位。

- **输入**：历史价格序列 + 近期重大事件（政策、开工、进出口、废钢到货等）
- **输出**：
  - 方向性倾向（偏强 / 偏弱 / 震荡）
  - 关键驱动因素
  - **反向信号** —— 什么情况会推翻这个倾向
- **硬约束**：
  - 强制标注「分析参考，非预测承诺」
  - 强制给出推翻条件
  - **禁止输出具体价位目标**，禁止买卖信号

**明确不做**：准确率承诺、点位、投资建议。

### 5.3 行业问答

**形态**：基于行业知识库的专业问答。

- **覆盖**：品类规格与等级定义、计价口径、杂质扣减规则、地区差异、行业术语、政策常识
- **约束**：
  - 答案可溯源到知识条目
  - 不确定就说不确定
  - 涉及价格数字时**引用简报数据**，不生成
  - 拒答投资 / 法律 / 税务意见

**明确不做**：代替简报给报价、预测未来价格、出具专业意见。

### 5.4 MVP 分层与成功标准

- **必须成立**：G1 —— 一批目标用户每天来看简报，并认为报价可信。
- **可以先薄**：情景推演与问答。但薄不等于不可信 —— 必须可溯源、不越界、说不确定时说不确定。
- **不许用可信度换功能数量。**

「报价可信」要做成**可测**：简报页每次访问后的一道单题评分（这份报价对你今天定进出价是否有用 / 是否可信），加上异常率、覆盖率。

## 6. MRD —— 用户、市场、价值

### 6.1 目标用户

**主（v1）**：回收站老板/采购、废品贸易商。决策 = **今天按什么价收、按什么价出**。

**次（v2）**：冶炼厂、利废企业、研究机构。

画像要点：

- 决策日频，价格敏感，手机 / 电脑上看
- 现在的信息来源：行业群、地方市场口头价、零散公众号
- 核心痛点：报价散、口径乱、不知道今天该按什么价进出
- 付费意愿：**未验证** —— 这是 v1 最大的商业未知

### 6.2 市场判断

- 再生资源回收利用万亿级市场，从业者数量大且高度分散。
- 现有玩家贵、重、面向大企业；中小从业者是被服务缺口。
- **待验证假设**：他们愿意为「每天可信的报价简报」持续来用（并最终付钱）。
- v1 的任务是验证**使用**，不是验证付费。付费等有留存再谈。

### 6.3 价值主张

> **「每天早上一份可信的废料报价与行情，够你今天定进出价。」**

差异化不在于数据独家（v1 没有），在于：

1. **轻** —— 不需要企业采购流程
2. **准** —— 口径统一、可溯源、异常隔离
3. **交互** —— 问答 + 情景推演，传统资讯商做不好

商业化（v2 草案，不在本次范围）：轻订阅（更多品类 / 更多地域 / 历史数据导出）、专业接口接入后的增值。**本次不设计付费墙。**

## 7. 关键技术

### 7.1 数据采集与治理（最难、最值钱，不是模型）

**采集层**

- **来源注册表**：每个来源记录类型（网页 / RSS / API）、覆盖品类与地域、更新频率、可信权重、ToS 状态
- **适配器**：每个来源一个抓取适配器，产出统一的「原始报价记录」
- **调度**：按天、错峰、失败重试、来源变更告警

**规范化层（数据资产的核心）**

- **主键**：品类 × 规格/等级 × 地域 × 日期
- **口径字典**：品类命名、等级划分、杂质扣减规则、计价单位（元/吨）
- **地域对齐**：市场 / 城市 / 区域三级；「全国」是聚合口径，必须标注
- 每条记录携带：来源、抓取时间、原始值、规范化值、校验状态

**Agent 校验层（你指定的运行方式）**

- **跨源对账**：同品类规格地域多源比对，偏离阈值 → 标记
- **时序异常**：日环比 / 周环比超阈值 → 隔离，**不进简报**
- **口径一致性**：单位、等级映射、重复记录
- **产出**：通过 / 隔离 / 需人工看，**全部留痕，可回溯 Agent 的判断依据**
- **人的角色**：只出现在异常队列和口径决策，不做日常整理

**留痕与可回溯（可信度的物理基础）**

- 原始抓取内容不可变存档
- 规范化与校验的每一步可重放
- 简报的每个数字可点回来源

### 7.2 简报生成

结构化数据 → 模板骨架 + LLM 写叙事。

- 数字来自库，不来自生成
- 涨跌计算在数据层完成，LLM 只解释
- 叙事可更正、可版本化

### 7.3 情景推演

- 时序特征（趋势、波动、季节）+ 事件库（政策 / 开工 / 进出口 / 到货）
- LLM 组装情景：方向倾向 + 驱动因素 + 推翻条件
- **硬约束**：禁用具体价位目标；强制输出推翻条件；强制免责声明

### 7.4 行业问答（RAG）

- 知识条目：规格等级、计价口径、术语、政策常识（版本化维护）
- 价格类问题：从报价库取数，不生成
- 不确定就说不确定；拒答投资 / 法律 / 税务

## 8. 已决定的「怎么做」

1. **核心数据模型**是规范化报价表（§7.1），三块能力都是它的视图。
2. **数据管线全 Agent 化**：采集、校验、异常隔离、留痕自动跑；人只进异常队列与口径决策。
3. **简报数字与 LLM 叙事分离** —— 数字来自库，叙事可更正。
4. **「趋势预测」对外改名「情景推演」**，禁用点位，强制推翻条件。
5. **问答的价格问题走库取数**，不走生成。
6. **网站形态**：公开简报页 + 轻注册看明细 / 趋势 / 问答。
7. **地域范围 v1**：5–8 个重点区域 / 市场，不是全国全量。
8. **品类范围 v1**：废钢、废铜、废铝、废纸、废塑料 五个核心品类，每品类先定核心规格/等级。

## 10. 我替你做的判断（每一项都可推翻）

1. **「车相关的」怎么理解** —— 你第 1 条写了「先服务车相关的 废钢/废铜/废铝/废纸/废塑料」，但第 2 条又只列了这五个品类。我按 **v1 覆盖这五个品类，其中报废汽车拆解是这些品类的重要来源渠道之一**来理解，**不限于车相关**。如果你的意思是「只做车相关报废件」，这条要改，范围会明显缩小。
2. **v1 地域范围 = 5–8 个重点区域/市场**，不是全国全量。理由：公开采集拿不到全国全量。
3. **「全国均价」保留，但必须标注为加工指标**，不是观测值。
4. **情景推演保留「方向倾向」**（偏强/偏弱/震荡），但禁用具体价位目标。
5. **网站形态 = 公开简报页 + 轻注册看明细/趋势/问答**。理由：简报要能被传播，明细与问答留注册做增长与留存。
6. **v1 不做移动 App。**
7. **「趋势预测」对外呈现为「情景推演」**，降低合规与期望风险。
8. **成功标准采用你的表述**（目标用户每天来看简报并认为报价可信），并把它做成可测的单题评分 + 异常率 + 覆盖率。
9. **v1 不做商业化 / 付费墙**，付费等留存验证后再谈。
10. **合规姿态**：只给事实与情景，不给投资建议；上线前做一次合规审查（备案 + 预测内容边界 + 采集合规，时点见 §14）。

## 11. 阶段与成功标准

| 阶段 | 内容 | 出口条件 |
|---|---|---|
| **P0 数据底座 + 简报** | 5 品类 × 核心规格 × 5–8 重点区域；每日采集 + Agent 校验 + 简报页 | G1 达成：一批目标用户每天来看，并认为报价可信 |
| **P1 推理与问答** | 情景推演、知识库问答 | 两块能力可信、可溯源、不越界 |
| **P2 增长与商业化** | 注册/订阅、更多品类与地域、专业接口接入 | 留存与付费假设验证 |

> **P0 当前交付出口按 §14 为「本地端到端流程跑通」**（采集 → 规范化 → Agent 校验 → 异常隔离 → 留痕 → 简报生成，可重跑、可回放）。
> 上表中的「G1 达成」是**对外上线之后**的验证指标，不是 P0 的交付门槛。

**v1 的唯一北极星指标**：目标用户的**每日回访**（次日 / 7 日回访率）+ **报价可信评分**。

**不承诺的指标**：实时性、全国覆盖度、预测准确率。

| # | 风险 | 应对 |

| 5 | **合规（公开预测内容）** | 已用「情景推演」形态规避点位与建议；上线前一次合规审查 |

> 风险 #1 与 #5 中的「上线前法务确认 / 合规审查」，按 §14 统一**推迟到对外上线之前**，不阻塞开发。
