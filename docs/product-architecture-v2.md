# Bee 产品架构 v2 —— 三大功能块与 Agent 运行方案

**状态**：提案 v1（2026-10-27）｜**基线**：`mrd-prd.md` v1.0、ADR-0001~0008、现有代码
**一句话**：把「日频报价库」升级成「看得懂的行情台」——列表像股票行情，点进去有价格、有当日情报、有情景推演，右侧随时能问。

---

## 0. 为什么要有这份文档

现有 MRD/PRD 定的是**产品边界与可信度红线**，本文定的是**实现形态**：页面怎么分、数据怎么流、Agent 怎么跑、分几期做。
与既有决策冲突的地方，本文显式标注（§10），不悄悄改。

---

## 1. 不变式（先立规矩，后面所有设计都受它约束）

1. **数字来自库，不来自模型**。LLM 只能写文字、给方向、做归因。
2. **每句话都要有证据**。情报、分析、回答都挂 `evidence_id`（序列点 / 新闻 / 知识条目），页面可点开。
3. **不给点位、不给买卖建议**。统一标注「分析参考，非投资建议」。
4. **每次 Agent 运行可审计**：模型、prompt 版本、输入引用、输出、耗时、成本，全部落 `agent_invocation`。
5. **历史可回放**：任一页面快照能重建出当时的数字与叙事版本。

## 2. 功能块一：行情（Markets）

### 2.1 信息架构

**`/` 行情总览（股票式列表）**

- 顶部三个范围页签：**国际 / 国内 / 区域**
- 每行 = 一条可交易口径的序列：品类 · 规格 · 市场/地区
- 列：最新价、日涨跌、周涨跌、更新时间、来源数、可信标记（正常/待复核/缺口）
- 支持按品类筛选、按涨跌幅排序
- 点击任意行 → 单品页

**`/m/[slug]` 单品页**

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 头部 | 最新价、涨跌、更新时间、口径说明（单位/含税/交货地） | `daily_quote` / `market_series` |
| 价格图 | 1M / 3M / 1Y / 2Y / 全部；分层对比（国际基准 vs 国内期货 vs 区域现货） | `series_point` |
| 数据表 | 最近 N 期，每行可展开溯源面板 | `series_point` → `raw_fetch` |
| 今日简评 | 涨跌归因，2–4 句，带引用 | `analysis_run` |
| 情报流 | 新闻卡片：标题、来源、时间、涉及品类标签 | `news_item` |
| 情景推演卡 | 方向倾向 + 驱动因素 + 推翻条件 + 置信度 | `analysis_run` |

**`/internal/status`**：运维页（已存在），补分析任务与新闻采集的健康度。

### 2.2 诚实的缺口表达

- 区域现货现在为 0 条 → 页面显示「区域现货：待接入」，**不留空白假装有**。
- 国际层目前只有 FRED 月频 → 图上明确标注「月频」，不与日频混画成一条线。

## 3. 功能块二：情报与分析（Intelligence）

### 3.1 新闻采集与结构化

- **来源**：RSS 优先，其次列表页；来源登记在已有 `source` 表（增加 `kind='news'`）。
- **抓取**：正文抽取 → 原始 HTML 进内容寻址存档（`raw_content`，落 Garage S3）。
- **抽取**（LLM，结构化）：标题、发布时间、涉及品类、地区、事件类型（政策/开工/进出口/价格/事故）、一句话摘要。
- **去重**：URL 规范化 + 正文 simhash。
- **合规**：库里只存摘要 + 原文链接，不全文转载；robots/ToS 状态记在 `source`。

### 3.2 每日分析（情景推演）

- **频率**：每品类每日 1 次，07:30 CST（早于用户上班）。
- **输入**：近 60 日该品类序列 + 近 7 日相关新闻 + 事件日历。
- **输出**（zod 校验的结构化 JSON）：

```json
{
  "scope": {"category": "废钢", "region": "华东"},
  "as_of": "2026-10-27",
  "direction": "偏强|偏弱|震荡",
  "horizon": "1w|1m",
  "drivers": [{"claim": "...", "evidence_ids": ["sp:...", "news:..."]}],
  "invalidators": ["若 ... 则本判断失效"],
  "confidence": "low|medium|high",
  "narrative": "80-150 字"
}
```

- **硬约束**：禁具体价位/目标价/买卖信号；必须给推翻条件；必须带证据。
- **落库**：`analysis_run` + `analysis_evidence`，按 `as_of` 版本化，可回看历史观点。

### 3.3 自评与回测

- 每周回看：上周方向判断 vs 实际周变动 → 方向命中率。
- 在单品页公开显示命中率（近 4 周 / 近 12 周），**诚实比吹牛更有说服力**。

## 4. 功能块三：问答（Q&A）

- **形态**：右侧抽屉，任何页面可开；上下文自动注入（当前单品、当前时间范围）。
- **三类问题，三条路径**：

| 问题类型 | 例 | 路径 |
|---|---|---|
| 数据类 | 苏州重废现在多少钱？ | 工具调用查库（**不生成数字**） |
| 知识类 | 重废和统废的区别？ | RAG 检索知识库（口径字典 + 术语） |
| 分析类 | 下周废钢会涨吗？ | 引用当日 `analysis_run` + 声明不确定性 |

- **工具集**（服务端函数，非自由发挥）：`query_series`、`get_latest_quote`、`search_news`、`get_analysis`、`search_knowledge`。
- **输出**：SSE 流式；每条回答带 `citations[]`；不确定时明确说不知道。
- **拒答**：投资建议、法律、税务。

## 5. 四个 Agent = 四类作业，不是四个常驻进程

| Agent | 触发 | 输入 | 输出 | 失败处理 |
|---|---|---|---|---|
| 行情采集 | 交易所收盘后 + 次日补采 | 交易所/FRED 接口 | `series_point` | 重试 3 次 → 异常队列 |
| 情报采集 | 每 30 分钟 | RSS/列表页 | `news_item` + 关联 | 跳过单源，告警 |
| 每日分析 | 07:30 每日 | 序列 + 新闻 | `analysis_run` | 保留上一版观点并标注异常 |
| 问答 | 用户请求 | 问题 + 页面上下文 | 流式回答 | 降级为"只取数不解释" |

**运行方式**：`pg-boss`（同库队列）+ 一个 worker 进程；每个作业幂等、可重跑、有台账。

**为什么不用「常驻 Claude Code 进程」**（ADR-0006 的延伸）：
- 生产运行时需要确定性、可重放、成本可预测；交互式编码代理三者都难保证。
- Claude Code 适合**开发期**写代码、跑迁移、调适配器；上线后由 worker 调模型 API。
- 结果等价：作业 = 一个 prompt + 一组工具 + 结构化输出校验，谁调用不重要，能不能审计才重要。

## 6. 系统架构

```
                     ┌──────────── Caddy (TLS / 反代) ────────────┐
                     │                                            │
  浏览器 ──────────▶ │  Next.js (RSC 页面 + /api + SSE 问答)       │
                     └───────┬───────────────────────┬────────────┘
                             │ 读                      │ 工具调用
                             ▼                         ▼
                    ┌──────────────────┐      ┌──────────────────┐
                    │  PostgreSQL      │      │  LLM 网关(可换)   │
                    │  业务表 + 台账    │      │  抽取/分析/问答    │
                    │  pgvector 知识库  │      └──────────────────┘
                    └────────▲─────────┘
                             │ 写
                    ┌────────┴─────────┐
                    │  worker (pg-boss) │──────▶ 交易所 / FRED / RSS
                    └────────┬─────────┘
                             ▼
                    ┌──────────────────┐
                    │ Garage S3 原档    │  raw_content 内容寻址
                    └──────────────────┘
```

| 组件 | 选型 | 现状 |
|---|---|---|
| Web | Next.js 16 App Router + Tailwind | 已有骨架与首页 |
| Worker | Node + pg-boss | **待建**（ADR-0005 已定，未实现） |
| 数据库 | PostgreSQL 18 | 已有 `bee-postgres` |
| 对象存储 | Garage（S3） | **已就绪**（共享中间件） |
| 缓存/限流 | Valkey | 已就绪，问答限流用 |
| 反代 | Caddy | 已就绪 |

**基础设施收口建议**：Bee 现在自带 `bee-postgres`，与共享中间件并存。建议用 `newapp bee` 分配独立库与 S3 桶，把 `bee-postgres` 退掉——隔离不变，运维少一套。**不改数据模型，只换连接串。**

## 7. 数据模型增量

复用已有：`source`、`raw_content`/`raw_fetch`、`market_series`/`series_point`、`daily_quote`、`pipeline_run`、`agent_invocation`。

新增 6 张：

| 表 | 关键字段 | 用途 |
|---|---|---|
| `news_item` | id, source_id, url, url_hash, title, summary, published_at, fetched_at, raw_fetch_id, event_type, simhash | 情报条目 |
| `news_series_link` | news_id, series_id, relevance, method | 新闻↔品类关联 |
| `analysis_run` | id, scope_type, scope_id, as_of, model, prompt_version, output_json, confidence | 每日观点 |
| `analysis_evidence` | analysis_id, evidence_type, evidence_id | 观点的证据链 |
| `knowledge_chunk` | id, doc_type, title, content, embedding vector(1024), version | 问答知识库 |
| `qa_message` | id, session_id, role, content, citations_json, model, tokens | 问答留痕（脱敏） |

索引：`news_item(published_at desc)`、`news_series_link(series_id)`、`series_point(series_id, obs_date)`、`knowledge_chunk` 向量索引（HNSW）。

## 9. 调度与成本

| 作业 | 频次 | 单次成本量级 | 备注 |
|---|---|---|---|
| 交易所日行情 | 3 次/日 | 0 | 纯抓取，无 LLM |
| FRED 月频 | 1 次/月 | 0 | 纯抓取 |
| 新闻抓取 | 48 次/日 | 0 | 抓取无 LLM |
| 新闻抽取 | 增量批次 | 小模型 | 只处理新增 |
| 每日分析 | 5 品类 ×1/日 | 强模型 ×5 | 可并行 |
| 问答 | 按需 | 中模型 | 限流 + 缓存常见问题 |

估算：每天 LLM 调用 < 100 次；抽取用便宜模型，分析用强模型，问答用中档。

## 11. 分期与验收

| 期 | 范围 | 验收标准 |
|---|---|---|
| **P1** 行情页 | 总览列表 + 单品页 + 图表 + 溯源 | 打开任一品类能看到真实价格曲线，每个数字点得回来源 |
| **P2** 情报流 | 新闻采集 + 抽取 + 单品页卡片 | 单品页每天有新新闻，且能标出涉及品类 |
| **P3** 每日分析 | 分析作业 + 观点卡 + 证据链 + 历史回看 | 每个观点都能点开 3 条以上证据；无点位承诺 |
| **P4** 问答 | 右侧抽屉 + 三类问题路径 | 数据类问题 100% 走库；知识类带引用；不确定会说不知道 |
| **P5** 预测基线 | 统计基线 + 回测面板 | 公开方向命中率，可对照基线 |

P1 先做，因为它是另外两块的地基——没有可信的行情页，情报和问答都没有落脚点。

## 12. 风险与开放问题

1. **新闻版权**：只存摘要+链接，全文留在原站；收到投诉可下线单条。
2. **区域数据缺失**：短期无解，靠采购或第一方；页面明示缺口。
3. **LLM 幻觉**：用"证据 ID 必填 + 数字只能来自工具"两道闸；缺证据则降级为不确定。
4. **大商所 WAF**：铁矿/焦炭/焦煤缺失，单独排期攻防或换源。
5. **成本失控**：问答限流 + 缓存 + 每日预算上限，超限降级。

## 13. 已拍板的事项（2026-10-27）

1. **不做登录**：所有页面公开可读，任何用户可看。
2. **分析粒度**：5 个品类每天各 1 次；品类可扩展，新增品类只加配置与适配器，不改表结构。
3. **基础设施收口**：Bee 已迁到共享中间件（Postgres 18 + Garage），连接串单点配置在 `DATABASE_URL`，换库只改一行。
4. **界面重构**：用户侧大规模重做，从宣传册式落地页改为专业行情台（总览列表 + 单品页 + 右侧问答抽屉）。
