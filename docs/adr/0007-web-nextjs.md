# ADR-0007 Web：Next.js（App Router / RSC）+ Tailwind（P0-4 引入）

**状态**：已定稿（P0-1，2026-10-26；P0-4 实现页面）｜**决策人**：CTO

## 背景

形态已定：网站，公开简报页（要被传播、被搜索引擎收录）+ 轻注册看明细/趋势/问答；
v1 不做 App、不做付费墙。骨架阶段只需一个能证明全链路连通的服务端页面。

## 决策

- **Next.js（App Router）**：公开简报页 SSR/ISR 渲染（SEO + 分享卡片），明细/问答页 RSC + 客户端交互。
- 数据获取：服务端组件直连 `@bee/db`（读库渲染），写路径一律走管线/API，页面永不直写。
- 样式 **Tailwind CSS** 在 P0-4 落地时引入（骨架不预置，保持最短路径干净）。
- 骨架阶段交付 `apps/web` 状态页（读各表计数），证明 Next ↔ PG ↔ 迁移链路可用。

## 为什么

- 「日更内容站 + 部分动态区」正是 Next 的舒适区；一个框架覆盖静态-ish 简报与动态明细两端。
- RSC 把溯源面板这类「点击展开证据链」的交互写起来最顺（服务端取链、客户端展示）。
- 工程代理对 Next 生态的生成质量与资料密度是全部候选里最好的。

## 弃了什么

- **Astro**：内容站匹配度极高，但明细/趋势/问答是交互型应用区，双框架混搭不值得；
  简报页的 SEO 需求 Next 已满足。
- **Nuxt（Vue）**：无决定性优势，团队栈统一 React。
- **纯 SPA（Vite + React）**：简报页 SEO/首屏分享直接失败，与「简报可传播」冲突。
- **WordPress / 无头 CMS**：把核心资产放第三方运行时，审计与管线一体化全断。
- ** Remix**：与 React Router 合流后定位重叠，生态位让给 Next。

## 影响

- P0-4 在 `apps/web` 内落简报页、溯源面板（`/api/trace/...` 契约见 `@bee/core/trace.ts`）、轻注册。
- 骨架不含 Tailwind/组件库；引入时作为一次独立小迁移，不与页面功能混在一个变更里。
